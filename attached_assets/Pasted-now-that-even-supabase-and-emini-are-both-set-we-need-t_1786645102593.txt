GitHub Actions variables and secrets
In GitHub, open:

Repository → Settings → Secrets and variables → Actions

Use Variables for non-sensitive build configuration:

VITE_SUPABASE_URL

Use Secrets for sensitive values:

VITE_SUPABASE_ANON_KEY
GEMINI_API_KEY
SUPABASE_ACCESS_TOKEN

The Supabase anon key is included in the browser bundle by design, so it is not a true secret. Storing it as a GitHub secret still prevents it from appearing in workflow configuration and logs, but Supabase RLS—not GitHub secrecy—must protect the data.

The workflow will use them like this:

env:
  VITE_SUPABASE_URL: ${{ vars.VITE_SUPABASE_URL }}
  VITE_SUPABASE_ANON_KEY: ${{ secrets.VITE_SUPABASE_ANON_KEY }}

And only a server-side build or deployment step should receive:

env:
  GEMINI_API_KEY: ${{ secrets.GEMINI_API_KEY }}

SUPABASE_ACCESS_TOKEN should only be passed to Supabase CLI or migration steps, never to the frontend or Electron renderer.

This setup will use GitHub Actions for repeatable Windows builds, while keeping the Gemini key out of the distributed application.
